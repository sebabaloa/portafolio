# portafolio

## Reglas

- Todo lo que entra aquí es público. El repo y el sitio en sebastianbaloa.com
  los lee cualquiera, así que en el repo no entra nada que no saldría en el sitio.
  *Por qué: GitHub Pages gratis exige repo público.*
- No se nombra a ninguna empresa ni cliente: ni en el texto, ni en logos, ni en
  colores corporativos, ni en nombres de tablas o rutas. Cada sistema se presenta
  como proyecto propio, con un contexto genérico («ERP de procura para una
  empresa de ingeniería»). *Por qué: el sitio muestra lo que Sebastián sabe
  construir, no expone a quienes lo contrataron.*
- Los datos de las demos se inventan de punta a punta y se notan ficticios. No se
  parte de datos reales, ni anonimizados. *Por qué: lo real de la tripulación y
  de los proveedores no puede salir en ninguna forma.*
- Las demos son maquetas sin backend vivo: el backend se explica en el panel
  «Cómo funciona», no se despliega. *Por qué: una demo encendida cuesta, se
  mantiene y la puede abusar cualquiera.*
- La portada se adapta a celular; las demos son solo de escritorio, con un aviso
  en pantallas chicas. *Por qué: son sistemas de oficina y se juzgan en pantalla
  grande.*
- Un solo `DESIGN.md` rige la portada y todas las demos; cada demo vive en su
  subruta (`/erp/`, `/buque/`, `/seguridad/`) y se distingue solo por su color de
  acento. *Por qué: el sitio se lee como una sola obra y ninguna demo se parece
  al producto real de la empresa.*
- El código que muestra el panel «Cómo funciona» se escribe para la demo, con
  nombres neutros; no se copia de los repos de las empresas. *Por qué: lo que
  nunca fue de la empresa no hay que limpiarlo.*
- HTML, CSS y JS a mano, sin framework ni paso de build. *Por qué: es un sitio
  estático y lo que no se compila no se rompe.*

## Dónde mirar

- Sistema visual → `DESIGN.md`
- Estado y tareas → tablero de Trello `portafolio`
